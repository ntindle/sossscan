## Results are leads, not guarantees

A scan reads file names, workflow text and settings, and its checks are heuristics. It can miss a problem, and it can report one that isn't there. A clean result doesn't mean a repository is secure. Treat each finding as a lead to check, and decide for yourself what to change.

The guide's advice, and its accounts of what projects in GitHub's Secure Open Source Fund did, summarize public posts and repositories that may be incomplete or out of date. Each quote links to its source.

## Changes you make with the fix app

The fix app changes a repository only when an admin of that repository asks it to:

- A settings fix changes one setting as soon as you confirm it. You can change it back in the repository's settings.
- A pull request fix opens a pull request after you've seen a preview of it. Nothing changes until someone merges it. The app never merges anything and never pushes to an existing branch.

You're responsible for the changes you confirm and the pull requests you merge, including whether they suit your project.
